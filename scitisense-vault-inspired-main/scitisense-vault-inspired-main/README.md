## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `app/page.tsx`. The page auto-updates as you edit the file.

This project uses [`next/font`](https://nextjs.org/docs/app/building-your-application/optimizing/fonts) to automatically optimize and load [Geist](https://vercel.com/font), a new font family for Vercel.

## Deployment updates

The build uses the hosting deployment ID or Git commit to version its assets and detect updates in open tabs. Hosts without these values or a Git checkout should set `NEXT_DEPLOYMENT_ID` to a unique release identifier before `npm run build`. Deploy the resulting build together across all server instances.

In production, `/api/version` returns the built release identifier with `no-store` headers. Keep this endpoint outside any custom CDN caching rules. Open, visible tabs check on return and every five minutes and offer a refresh when the release changes. Visitors can finish forms before refreshing.

After deploying, confirm `/api/version` reports the new release and that the production domain serves that deployment. A tab loaded before this update first needs a normal refresh to receive the update checker.
